# TraumChatRoom 审查发现清单（对抗复核定稿）

> 产出：Phase 2（doubt-driven-development 对抗复核）。
> 方法：50 条初始疑点（`01-业务逻辑梳理.md`）拆 3 域，各由独立 fresh-context 对抗 reviewer 核证；本文件为 RECONCILE 定稿。
> 结论口径：`✅成立` / `⚠️修正`（成立但证据/影响需修正）/ `❌不成立` / `🔺新增`（reviewer 发现的遗漏项）。
> 分级：P0=安全/隐私（必须修）· P1=功能缺陷（应修）· P2=性能/一致性（可修）。

## 一、P0 安全与隐私（9 项）

|---|---|---|---|---|
| P0-1 | **JWT 签名密钥硬编码默认值 → 可伪造任意 token（最高危）** | 🔺新增 | `application.yml:56` `${JWT_SECRET:+j7Wl...}`，`+:` 语义=无环境变量则用硬编码默认密钥；源码可见即可签发任意 `sub` 的 HMAC token，直接进 `/api/admin/**`（`SecurityConfig.java:86`） | 密钥必须外置且无硬编码默认值；启动时校验环境变量存在；生产强制注入 |
| P0-2 | **存储型 XSS → 双 token 窃取、账户接管** | ✅成立 | `MessageItem.vue:44` `v-html` 渲染 `message.content` 未转义；`:189-194` 只做 `@` 替换不回义；后端不滤 HTML（`WebSocketChatController.java:118-137`）；token 存 localStorage（`utils/token.js`） | 前端先 `escapeHtml` 再高亮；禁 v-html 渲染用户内容；后端可选 HTML 白名单/清洗；前端重写覆盖 |

| P0-7 | **游客过期/被删用户请求 → 500 而非 401** | ✅成立 | `JwtAuthenticationFilter.java:54` → `UserDetailsServiceImpl.java:45-58` 抛 `UsernameNotFoundException`，在 ExceptionTranslationFilter 之前冒泡 → 500 | filter 捕获 `UsernameNotFoundException` 转 401 |

## 五、执行优先级建议

1. **P0-1 ~ P0-9**：安全/隐私，Phase 3 第一优先（含凭据外置、XSS、私聊权限、文件下载、401、CORS、AI 隔离）。
2. **P1-6 / P1-11 / P1-12**：三处"功能自毁/数据不可见"级缺陷，紧跟其后。
3. **其余 P1、P2**：按依赖批量推进，每项配单元测试（TDD 红→绿）。
4. 前端问题（P0-2/P0-3 前端侧、P1-6~9、P2-15、X-22）由 Phase 4 全量重写统一覆盖。
