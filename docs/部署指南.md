# TraumChatRoom 阿里云部署指南

> 适用环境：Ubuntu 24.04 轻量服务器（2核2G/40G，swap 2G），1Panel 面板 + OpenResty 反向代理
> 技术栈：Spring Boot 4.0.5 (Java 21) + Vue 3/Vite 8 + MySQL 8.0.46 + Redis 8.6.3 + WebSocket (STOMP/SockJS)
> 部署方式：传统手动部署（systemd 守护 jar + OpenResty 托管前端并反代）

## 目标架构

```
浏览器 → https://traums.cn
           │
   1Panel OpenResty (80/443) 托管网站目录 /www/sites/TraumSpace/index + 反代
           ├── /api/*  → 127.0.0.1:8080
           └── /ws/*   → 127.0.0.1:8080 (WebSocket 升级)
                                │
                     Spring Boot jar (systemd 守护, 仅回环)
                                │
                  MySQL 8.0.46 (ChatRoomDB) + Redis 8.6.3
```

## 阶段 1 — 本地代码修改（5 处，必改）

**① `src/main/resources/application.yml:38`** — `file.upload-dir` 改为环境变量注入：
```yaml
file:
    upload-dir: ${FILE_UPLOAD_DIR:/home/traums/javawork/uploads}
```
> 生产通过环境变量注入 `/home/traums/javawork/uploads`，消除硬编码 Windows 路径。

**② `src/main/resources/application.yml:71`** — CORS 白名单改为可注入：
```yaml
cors:
  allowed-origins: ${CORS_ALLOWED_ORIGINS:http://localhost:5173,http://localhost:3000}
```

**③ `ChatRoomVue/.env.production`** — 改为真实域名：
```
VITE_API_URL=https://traums.cn
```
> 前端 axios 与 WebSocket 均使用该值（`useWebSocket.js:38` 拼接 `${baseUrl}/ws`），同源走 OpenResty，无跨域问题。

**④ `src/main/resources/logback-spring.xml:9`** — 日志目录改为环境变量注入：
```xml
<property name="LOG_DIR" value="${LOG_DIR:-./logs}"/>
```
> 生产通过 `.env` 的 `LOG_DIR` 将日志指向 `/home/traums/javawork/run/log`；本地无该变量时回退 `./logs`。

**⑤ `src/main/java/.../service/impl/UserServiceImpl.java`** — 头像路径拼接改为 `Paths.get()` 规范化（修复 `uploadsavatars` 问题）：
```java
// :189 原 uploadDir + "avatars/" → 改为
String avatarDir = Paths.get(uploadDir, "avatars").toString() + File.separator;
// :321 原 new File(uploadDir + relativePath) → 改为
File file = new File(Paths.get(uploadDir, relativePath).toString());
```
> ⚠️ 配置 `FILE_UPLOAD_DIR` 结尾**不要带斜杠**（如 `/home/traums/javawork/uploads`）。此修复已使路径拼接不受斜杠影响，旧版若在服务器产生了错误目录 `uploadsavatars` 需手动删除。

> 无需修改 `application-prod.yml`，它已声明从环境变量读取 `DB_URL / DB_USERNAME / DB_PASSWORD / REDIS_HOST / REDIS_PORT / REDIS_PASSWORD / AI_API_KEY / JWT_SECRET`。`application-dev.yml` 中的硬编码密钥仅供本地联调，不影响生产。

```bash
# AI

```

- `JWT_SECRET` 生成命令：`openssl rand -base64 32`（项目要求 Base64 解码后 32 字节）
- `REDIS_PASSWORD`：Redis 已设密码则填实际值，未设则留空
- systemd EnvironmentFile 中的 `!` 等特殊字符无需 shell 转义

**② systemd 服务** `/etc/systemd/system/traumchat.service`：

> **推荐**：跳过本步手动创建，直接跳到「阶段 4.5」运行 `./manage.sh setup` 自动生成。以下为手动创建方式（供参考）。

```ini
[Unit]
Description=TraumChatRoom Spring Boot
After=network.target mysql.service redis-server.service

[Service]
User=traums
Group=traums
WorkingDirectory=/home/traums/javawork/backend
EnvironmentFile=/home/traums/javawork/backend/.env
ExecStart=/usr/lib/jvm/java-21-openjdk-amd64/bin/java -Xms256m -Xmx512m -jar /home/traums/javawork/backend/traumchat.jar --spring.profiles.active=prod --server.address=127.0.0.1
Restart=on-failure
RestartSec=10
SuccessExitStatus=143

[Install]
WantedBy=multi-user.target
```

> JDK 实际路径用 `readlink -f $(which java)` 确认后替换。
> `--server.address=127.0.0.1`：只监听回环，公网安全组不开 8080。
> 日志目录由 `.env` 中 `LOG_DIR` 指定（`run/log/`），由 `logback-spring.xml` 的 `${LOG_DIR:-./logs}` 读取。

> 若手动创建了 service 文件，初始化命令如下（脚本方式见阶段 4.5）：
> ```bash
> sudo systemctl daemon-reload
> sudo systemctl enable --now traumchat
> ```

### 5.4 编辑站点配置（完整替换）

1Panel 面板 → 网站 → `TraumSpace` → 配置文件，**整块替换**为：

```nginx
server {
    listen 80;
    server_name traums.cn;
    index index.html;
    access_log /www/sites/TraumSpace/log/access.log main;
    error_log /www/sites/TraumSpace/log/error.log;

    # 安全防护（1Panel 默认，保留）
    location ~ ^/(\.user.ini|\.htaccess|\.git|\.env|\.svn|\.project|LICENSE|README.md) {
        return 404;
    }
    location ^~ /.well-known/acme-challenge {
        allow all;
        root /usr/share/nginx/html;
    }
    if ( $uri ~ "^/\.well-known/.*\.(php|jsp|py|js|css|lua|ts|go|zip|tar\.gz|rar|7z|sql|bak)$" ) {
        return 403;
    }

    root /www/sites/TraumSpace/index;

    # SPA fallback（History 模式必需，刷新 /chat 等子路径不 404）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源长缓存（文件名含 hash，安全）
    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # 后端 API 反代
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }

    # WebSocket 反代（SockJS 必需，含 Upgrade 头）
    location /ws/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 300s;
    }
}
```

### 5.5 关键点说明
- **`try_files $uri $uri/ /index.html`**：前端用 `createWebHistory()`（`router/index.js:57`），刷新子路径必需，否则 404
- **删除 `error_page 404 /404.html`**：1Panel 默认配置会跳去不存在的 404 页，SPA 下有害；改为 fallback 到 index.html
- **`/ws/` 的 `Upgrade/Connection`**：SockJS 升级必需，面板默认反代不带，必须手写
- **`/assets/` 长缓存**：文件名含 hash，发布新版自动换 URL，无缓存失效问题
- **root 路径**：容器内 `/www/sites/` ↔ 宿主机 `/opt/1panel/www/sites/` 为挂载映射，nginx 配置用容器内路径

### 5.6 重载 + 安全组 + 验证
- 1Panel 面板「网站 → 重载」或 `docker exec 1Panel-openresty nginx -s reload`
- 阿里云安全组放行 **80、443**（8080 不开放）
- 验证：
  ```bash
  curl -I http://traums.cn              # 200
  curl http://traums.cn/chat            # 返回 index.html（SPA fallback 生效，非 404）
  curl http://traums.cn/api/auth/guest  # JSON（反代通）
  ```

## 常见故障对照

- **前端白屏** → 检查 OpenResty 站点根目录指向 `/opt/1panel/www/sites/TraumSpace/index`、`dist` 是否已解压为 `index.html` 层级。
- **刷新子路径 404** → nginx 缺 `try_files $uri $uri/ /index.html;`（SPA fallback），或残留 `error_page 404 /404.html`。
- **WS 连不上** → 99% 是 `/ws/` 少了 `Upgrade/Connection` 头。
- **脚本报 `bash\r` / `No such file or directory`** → Windows 复制的文件带 CRLF，执行 `sed -i 's/\r$//' manage.sh`。
- **头像保存到 `uploadsavatars`** → `FILE_UPLOAD_DIR` 结尾斜杠导致的拼接问题，用新版 jar（已用 `Paths.get()` 修复）；旧错误目录 `rm -rf /home/traums/javawork/uploadsavatars`。
- **登录 500 / 连库失败** → 查 `run/log/app-error-*.log`，确认 `.env` 的 DB 参数与 MySQL8 `caching_sha2_password`（URL 已带 `allowPublicKeyRetrieval`）。
- **触发器导入报 1064/1054** → SQL 文件触发器未用 `DELIMITER` 包裹，用仓库内 `重构数据库.sql`（已修复）。
- **OOM** → 看 `systemctl status traumchat`；JVM 512M + MySQL buffer_pool 调 256M（`/etc/mysql/mysql.conf.d/mysqld.cnf`）+ swap 2G 兜底。
