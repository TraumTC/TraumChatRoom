# TraumChatRoom 技术栈详解(面试讲述版)

落盘位置:`docs/05-技术栈详解-面试版.md`(不改任何业务代码)。以下为文档全文。

---

## 0. 项目一句话定位

基于 **Spring Boot 4 + Vue 3** 的前后端分离实时聊天室:JWT 多设备会话管理、STOMP 实时消息、好友体系、Redis 承载的限流/幂等/在线状态/未读,集成 DeepSeek AI 助手与 Trie 敏感词过滤。

## 1. 后端技术栈

### 1.1 语言与构建
| 技术 | 版本 | 用途与讲点 |
|---|---|---|
| Java | 21 (LTS) | 使用了 record(敏感词库快照 `WordBook`)、switch 表达式(好友状态映射)、`Math.ceilDiv` 等新特性 |
| Maven | mvnw wrapper | 版本锁定、annotationProcessorPaths 配 Lombok |

### 1.2 Spring Boot 4.0.5(核心容器)
- 引入 starter:**webmvc、websocket、security、data-redis、webflux、validation、test** + aspectjweaver。
- **外部化配置**:`@Value` + `@ConfigurationProperties(FileStorageConfig)`,敏感项全部走环境变量占位符 `${DB_PASSWORD:}`;`application-dev/prod.yml` 双 profile,prod 无任何默认密钥。
- **启动fail-fast**:`JwtUtil.@PostConstruct` 校验密钥缺失/不足 32 字节直接拒绝启动。
- 面试讲点:为什么 CSRF 可以关(无 Cookie 会话、纯 Bearer 头,但 refreshToken Cookie 要靠 SameSite=Lax 兜底);SessionCreationPolicy.STATELESS。

### 1.3 Spring Security + JWT 认证体系(最大亮点)
- **SecurityFilterChain**(Lambda DSL 新式写法):公开路径白名单 → `/api/admin/**` hasRole("ADMIN") → anyRequest().authenticated;自定义 401/403 返回 JSON 而非默认登录页。
- **BCryptPasswordEncoder** 存密码(自带随机盐,讲点:为什么不用 MD5+盐)。
- **JJWT 0.12.6**:`parseSignedClaims` + `Keys.hmacShaKeyFor`(HMAC-SHA256,启动校验 ≥32 字节)。
- **双 Token 设计**:accessToken 30 分钟(claim `token_type=access`,防止 refresh token 被当接口凭证用)、refreshToken 7 天(claim `sid` = 会话 ID)。
- **RefreshTokenStore(Redis 会话中心)**:只存 SHA-256 哈希不存原文;**Lua 原子轮换**(旧 token 校验+写入新 token+维护会话索引集合一条脚本完成,天然防并发重放);`revokeAll` 支持改密/禁用全端下线。
- **JwtAuthenticationFilter(OncePerRequestFilter)**:解析 token → 校验 Redis 会话仍活跃 → 加载 UserDetails → 写 SecurityContext;Redis 故障时返回 503(认证链 fail-closed);用户不存在时清上下文返回 401 而非 500。
- **多设备并行登录**:每个会话独立 `chat:refresh:{user}:{sid}`,登出只撤当前设备。
- **refreshToken 走 HttpOnly Cookie**(path=/api/auth、SameSite=Lax、secure 可配),accessToken 只存前端内存。

### 1.4 WebSocket 实时通信(STOMP)
- **@EnableWebSocketMessageBroker**:端点 `/ws` + **SockJS 降级**;简单代理 `/topic`(广播)/`/queue`(点对点),用户前缀 `/user`,应用前缀 `/app`。
- **@MessageMapping** 四个入口:群聊 `/space`、私聊 `/private.message`、心跳 `/heartbeat`、状态同步 `/sync-state`;`SimpMessagingTemplate.convertAndSend / convertAndSendToUser` 推送。
- **两层认证**:HandshakeInterceptor(URL/头取 token)+ ChannelInterceptor 在 STOMP CONNECT 帧取 `Authorization` 头设置 Principal(讲点:为什么 CONNECT 阶段才能拿 Principal)。
- **在线状态 = Redis 两级 ZSet 引用计数**:`chat:online:sessions:{user}`(会话级,score=最后心跳)+ `chat:online:users`(聚合级)。上线/下线/心跳三个 Lua 脚本,注册前先清僵尸会话(进程被杀、DISCONNECT 丢失可自愈);只有"首会话建立/末会话断开"才广播,避免多设备抖动引发广播风暴。
- **传输层调优**:入站线程池(20/50、队列 1000、CallerRunsPolicy)、消息体 128KB 上限、发送时限 20s;应用层 20s 心跳 + STOMP 协议心跳 10s。

### 1.5 MyBatis + MySQL
- mybatis-spring-boot-starter 4.0.1;7 个 XML mapper:resultMap、`<if>/<where>/<foreach>` 动态 SQL、批量 IN 查询;`map-underscore-to-camel-case`。
- **SQL 安全**:全项目无一处 `${}`,LIKE 也走 `CONCAT('%',#{kw},'%')` 参数化。
- **索引设计**(面试高频):message 表三条复合索引都以 `deleted_at` 参与且以 `id` 收尾——因为所有查询都带 `deleted_at IS NULL` 且按 `ORDER BY id` 游标翻页,用 created_at 收尾撑不起排序;`idx_unread` 与 `idx_private_history` 列序相反,分别服务正/反向查询(实测覆盖索引耗时减半)。
- **游标分页**:`WHERE id < #{cursor} LIMIT size+1` 多查一条判断 hasMore,替代 offset 深翻页。
- **软删除**:user/message 带 deleted_at,查重用 `IncludingDeleted` 系列避免撞唯一键 500。
- **N+1 治理**:好友列表/申请列表批量预取用户 Map;在线列表昵称解析 = 1 次 IN 查询 + 1 次 Redis pipeline(原来 100 人在线 100 次往返)。
- 数据库层:外键(SET NULL/CASCADE)、改名触发器、utf8mb4。

### 1.6 Redis(五大应用场景)
1. **缓存 Cache-Aside**:用户信息缓存;**事务提交后失效**(`TransactionSynchronizationManager.registerSynchronization.afterCommit`,防止提交前被旧值回填);冷缓存击穿用 64 桶本地锁互斥回源。
2. **限流**:固定窗口 Lua(`GET→false 则 SET+EX,否则 INCR`,原子无竞态);HTTP 注解版(按用户)与 WS 发送/AI 调用版共用 RedisRateLimiter;Redis 挂掉时认证/限流 fail-closed。
3. **幂等**:SETNX + TTL(上传/好友申请/消息 clientId);业务异常删除 key 允许重试。
4. **登录防爆破**:用户名 5 次/15 分钟 + IP 10 次/30 分钟,INCR+TTL+锁定一条 Lua 原子完成。
5. **业务状态**:游客信息 Hash(2h TTL)、私聊已读游标 Hash(90 天 TTL)、@提及未读 ZSet(score=messageId,用 ZREMRANGEBYSCORE 精确剔除,替换了有子串误删 bug 的旧 List 方案)。
- 序列化统一 StringRedisSerializer,JSON 由业务层 ObjectMapper 处理。

### 1.7 AOP 切面(三个自定义注解)
- `@RateLimit` → RateLimitAspect:按"用户+业务 key"限流,超限抛 429。
- `@Idempotent` → IdempotentAspect:读 `X-Request-Id` 头,SETNX 抢占,失败释放;讲点:为什么不用 JVM 本地锁(多实例)。
- `@LogOperation` → OperationLogAspect:`@AfterReturning/@AfterThrowing` 双回调;detail JSON 手工转义并按 SENSITIVE_KEYS 脱敏(password/token/secret);异常时只记 `BusinessException.message` 或异常类名,防堆栈入库。
- 讲点:切面内注入 HttpServletRequest 的原理(request 作用域代理)。

### 1.8 WebFlux WebClient(AI 集成)
- 单例 `aiWebClient`(连接池复用)调 DeepSeek chat/completions;`.timeout(30s).block()` 放在**独立线程池** aiTaskExecutor(3/10/队列50)执行,不阻塞 WS 入站线程。
- 服务端硬截断 AI 回复(max-reply-chars,处理代理对/句末优雅收尾);上下文按 session_key 存 MySQL,只留 20 条;定时任务(每天 3:17,错峰)分批清理过期会话。

### 1.9 其他
- **Bean Validation**:`@Valid + @NotBlank/@Size/@Pattern`(用户名字符集白名单、密码必须含字母+数字)。
- **Jackson + jsr310**、**Lombok**、**Logback**(SizeAndTimeBased 滚动、30 天/1GB 上限、springProfile 分环境、ERROR 单独归档)。
- **@Scheduled** 两处定时任务(在线僵尸清理 fixedRate 60s、AI 上下文清理 cron)。
- **JUnit 5 + Mockito**:17 个测试类(切面、全局异常、WS 控制器、Trie、过滤器、JWT、令牌存储等)。

### 1.10 设计模式与算法(面试加分点)
| 模式/算法 | 落点 |
|---|---|
| 策略+工厂 | MessageHandlerFactory 按 type 分发 text/image/file 处理器 |
| 不可变快照 + volatile 安全发布 | 敏感词库刷新:旁路构建新 Trie → 单次引用替换,读线程永远看到完整词库,刷新失败旧库继续生效 |
| Trie 前缀树 | 敏感词 O(n) 匹配,最长匹配 + 级别(1 替换/2 拦截) |
| 解压炸弹防护 | 头像上传:ImageReader 只读 header 校验真实格式与像素量 → setSourceSubsampling 解码期降采样,堆占用与源图分辨率解耦 |
| 引用计数 | 多设备会话(sid)与在线状态(会话 ZSet)共用同一思想 |
| 游标分页 / 幂等 / 限流 / 令牌轮换 | 见上文 |

**前端安全与健壮性亮点**(面试重点讲):
1. **XSS**:全项目仅一处 `v-html`(消息气泡),采用"先 escapeHtml 整体转义,再对 @提及片段高亮"的安全顺序,输入不可逃逸。
2. **Token 管理**:accessToken 只在内存(刷新页面靠 HttpOnly Cookie 静默恢复);迁移代码主动删除旧版本 localStorage 里的明文 token。
3. **乐观更新对账**:私聊消息本地先显示(负数临时 ID + clientId),后端回传真实消息后按 5 秒窗口替换;send-error 按 clientId 精确移除。
4. **竞态防护**:私聊历史加载用递增序号丢弃过期响应;快速切会话、滚动加载、隐藏容器补偿(scrollHeight 增量校正)都有专门处理。
5. **身份判定唯一入口**:`isMyMessage` 优先比 id、游客退回比 username,注释明确"不能比昵称,昵称可重复"。

## 3. 整体架构叙述(30 秒电梯稿)

"这是一个前后端分离的实时聊天室。HTTP 走 REST + JWT:accessToken 只存前端内存、30 分钟短时效,refreshToken 放 HttpOnly Cookie 并在 Redis 按会话哈希存储、原子轮换,支持多设备与全端下线。实时通道是 STOMP over WebSocket,SockJS 降级,服务端用 SimpMessagingTemplate 做广播和点对点。Redis 承担了五类职责:用户缓存(Cache-Aside+事务后失效)、限流(Lua 固定窗口)、幂等(SETNX)、登录防爆破、以及在线状态两级 ZSet 引用计数。数据层 MyBatis+MySQL,复合索引针对游标分页设计,全参数化无注入。横向能力上做了 AOP 限流/幂等/操作日志三个切面、Trie 敏感词过滤(不可变快照热更新)、WebClient 集成 DeepSeek AI 助手。前端 Vue3+Pinia+Vite,重点解决了 token 刷新竞态(Web Locks)、消息乐观更新对账、虚拟滚动性能和 XSS 转义顺序这几个问题。"

## 4. 面试高频追问与答题要点

1. **JWT 不是无状态吗,为什么还要查 Redis?** —— 换取主动失效能力:登出、改密、禁用立即生效;副作用是每次请求多一次 Redis 往返,用 hasKey O(1) 控制。
2. **限流/幂等为什么必须 Lua?** —— GET+INCR+EXPIRE 分开执行存在竞态(首计数可能丢失 TTL);脚本内原子完成,且 DefaultRedisScript 缓存 SHA1 走 EVALSHA。
3. **缓存一致性怎么保证?** —— 先更库后删缓存(Cache-Aside),删除挂在事务 afterCommit 回调,避免"事务未提交、并发请求把旧值重新回填"。
4. **多设备登录怎么设计?** —— token 带 sid,Redis 按 `user:{sid}` 一会话一 key,会话集合做索引;在线状态用会话 ZSet 引用计数,最后一个会话断开才判离线。
5. **refreshToken 为什么放 HttpOnly Cookie?** —— XSS 拿不到;SameSite=Lax 兜底 CSRF;path 限定 /api/auth 缩小暴露面;配合轮换实现盗用检测(旧 token 复用即轮换失败)。
6. **消息不丢/不重怎么保证?** —— 客户端 clientId + 服务端 SETNX 幂等去重;本地乐观消息由回传/错误事件对账修正。
7. **在线状态怎么做到准确?** —— 心跳 ZSet + 定时清理僵尸成员 + 下线脚本顺带清扫,三层兜底自愈。
8. **敏感词过滤怎么热更新?** —— 旁路构建新 Trie 后 volatile 引用替换,读侧无锁、无中间态(对比:原地 clear+重建会让刷新窗口内过滤失效甚至永久停在空库)。
9. **AI 有什么风险怎么防?** —— 提示注入(系统提示词防护+服务端字数硬截断)、上下文按用户隔离、限流、定时清理防表膨胀。
10. **头像上传为什么慢/怎么防打爆内存?** —— 图片解码是大头:三层防护(真实格式校验、header 像素预检、解码期降采样),再服务端统一压成 256 JPEG。
